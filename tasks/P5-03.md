# P5-03: Synthetic-injection recovery test

- **Phase:** P5
- **Model:** sonnet
- **Deps:** P2-08, P4-01, P4-02, P5-01
- **Size:** ~110 lines

## Goal
The sanity check in PLAN.md 3.4. Inject pump-and-dump episodes into a synthetic panel, run the feature pipeline and the detectors, and confirm the detectors find the injected episodes. Until this passes, results on real cases mean nothing.

## Files
- `src/saham_gorengan/evaluation/recovery.py` (new)
- `tests/test_evaluation_recovery.py` (new)

## Interface
```python
def run_recovery(seed: int = 0, n_tickers: int = 60, n_pumps: int = 6, k: int = 10, lead: int = 0,
                 start: date = date(2024, 1, 2), end: date = date(2024, 12, 31)) -> dict[str, float]: ...
    """Returns recall@k per detector: {"rank_ret": ..., "rank_vol": ..., "rank_rule": ..., "composite": ...}."""
```

## Behaviour
- Draw `n_pumps` distinct tickers and start dates with `numpy.random.default_rng(seed)`:
  - each start is a trading day at least 80 trading days after `start`, so feature windows can warm up;
  - each start leaves room for the 15-day pump plus dump before `end`.
- Build `synthetic_bars(n_tickers, start, end, seed, pumps)` with default `Pump` parameters.
- Pipeline: `build_features` → `baseline_scores` and `composite_scores` (default components).
- **Why 2024:** the default dates are in 2024 because 2022's 7% ARB would make synthetic dump days (-12%) look like corporate actions, and P2-08 would mask them. Say this in the docstring.
- **Windows:** one per pump, from its first pump day to its last dump day (15 trading days), with `window_id` f"PUMP-{ticker}".
- Score each detector's rank column with `window_metrics(..., k=k, lead=lead)` and return `recall_at_k` per detector.

## Acceptance
`tests/test_evaluation_recovery.py`:
- `test_composite_recovers`: `run_recovery(seed=0)["composite"] >= 0.8`.
- `test_baselines_recover`: `rank_ret >= 0.8` and `rank_vol >= 0.8` for seed 0.
- `test_deterministic`: two calls with seed 1 return identical dicts.
- `test_runtime`: `run_recovery(seed=2)` finishes in under 60 seconds.
- `test_bad_dates`: a range too short to fit warm-up plus pump raises `ValueError`.

If a recovery threshold fails, report the observed recalls. Do **not** lower the threshold or tune pump parameters to pass. The planner decides whether the detector or the test is wrong.
