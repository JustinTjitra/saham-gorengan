# P5-05: Evaluation report generator

- **Phase:** P5
- **Model:** sonnet
- **Deps:** P5-01, P5-01b, P5-04
- **Size:** ~130 lines

## Goal
Turn evaluation results into a readable Markdown report (`reports/evaluation.md` later), with the comparisons PLAN.md 3.4 makes mandatory side by side: recall against placebo windows and a random ranker, alert burden, and per-case results. The report names OJK-labelled cases only, never other stocks.

## Files
- `src/saham_gorengan/evaluation/report.py` (new)
- `tests/test_evaluation_report.py` (new)

## Interface
```python
@dataclass
class DetectorResult:
    name: str
    case_metrics: pd.DataFrame       # window_metrics output on the real labelled windows
    placebo_metrics: pd.DataFrame    # window_metrics output on placebo windows
    random_metrics: pd.DataFrame     # window_metrics on real windows using random_ranks
    burden: dict[str, float]         # alert_stats output

def render_report(results: Sequence[DetectorResult], k: int, lead: int, title: str = "Evaluation") -> str: ...
```

## Behaviour
- The output is Markdown text, in this order:
  1. `# {title}`, then one line naming `k` and `lead` and noting that results are statistical anomaly detection on labelled cases, not findings.
  2. **Summary table**, one row per detector: recall@k on cases, recall@k on placebos, recall@k with the random ranker, median `share_in_topk` on cases, median `first_flag_offset` on found cases, flags/day, distinct tickers. Numbers have 2 decimals, offsets are integers, and missing values show as "n/a".
  3. **Per-case table**: one row per window_id, with each detector's `found` (yes/no) and `first_flag_offset`. Rows are sorted by window_id.
  4. A note under the tables: "Placebo and random baselines are mandatory comparisons (PLAN.md 3.4); a detector is only useful where it clearly beats both."
- Use `recall_at_k` for the recall cells. Never print a ticker that is not in `case_metrics`.
- An empty `results` raises `ValueError`. So do detectors whose `case_metrics` hold different window_id sets.
- The output is deterministic: the same inputs give the same text.

## Acceptance
`tests/test_evaluation_report.py`, with two hand-built detectors over three windows:
- `test_summary_numbers`: the summary row for detector A shows the expected recall values with 2 decimals (for example "0.67" for 2 of 3 found) and "n/a" where a median is undefined.
- `test_per_case_table`: each window has one row with yes/no per detector, sorted by window_id.
- `test_mandatory_note_present` and `test_title_and_params`.
- `test_no_foreign_tickers`: tickers that appear only in the placebo frames never appear in the output.
- `test_bad_input`: empty results and mismatched window sets raise.

Writing the file and wiring it to real data (a later pipeline chunk); plots.
