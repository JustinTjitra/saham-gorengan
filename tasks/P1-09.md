# P1-09: Backfill command (offline-tested)

- **Phase:** P1
- **Model:** sonnet
- **Deps:** P1-02, P1-03
- **Size:** ~170 lines

## Goal
The code that pulls history from a `DailySource` into the private store, month by month, in a way that survives interruptions and bad tickers. This chunk writes and tests the code offline against a fake source. Running it for real needs Yahoo's hosts, which the loop's current session can't reach (see Q3), so a later data chunk runs it.

## Files
- `src/saham_gorengan/backfill.py` (new)
- `tests/test_backfill.py` (new)

## Interface
```python
@dataclass
class BackfillReport:
    months_done: list[str]        # "YYYY-MM" written this run
    months_skipped: list[str]     # already complete in the state file
    rows_written: int
    failed: list[tuple[str, str, str]]  # (month, ticker, error message)

def backfill(source: DailySource, tickers: Sequence[str], start: date, end: date,
             root: str | Path | None = None, batch_size: int = 50, pause: float = 1.0,
             sleep: Callable[[float], None] = time.sleep) -> BackfillReport: ...
```

## Behaviour
- `root` resolves through `store_root(root)` from `store.py`. Raise `ValueError` if `start > end` or `tickers` is empty.
- Split [start, end] into calendar months, clipped to start and end. For each month, in order:
  - skip it if the state file `<root>/state/backfill.json` lists it as complete **for this source name and an identical ticker set**;
  - otherwise fetch the tickers in batches of `batch_size`, calling `sleep(pause)` before every source call except the very first of the run;
  - if a batch raises `BarsValidationError` or `SourceError`, retry that batch **one ticker at a time**. A ticker that still fails is recorded in `failed` and skipped; the others are kept;
  - write the month's bars with `write_bars` (nothing is written for an empty month), then record the month as complete in the state file.
- The state file is JSON: `{"<source name>": {"tickers_sha1": "<hex>", "complete": ["2024-01", ...]}}`. The hash is SHA-1 of the sorted, newline-joined tickers. A changed ticker set starts that source's list afresh. Write it atomically (temp file plus `os.replace`), as the store does.
- A month with failed tickers is still marked complete. A later run with `tickers=[that ticker]` (a different ticker set) can fill it in.
- Never write market data inside the repo; `store_root` already enforces that.
- Log progress with `logging.getLogger(__name__).info`.

## Acceptance
`tests/test_backfill.py`, with a fake source built on `synthetic_bars` (it returns the requested tickers' rows in the date range and counts its calls), and `tmp_path` as root:
- `test_backfill_writes_months`: Jan to Mar 2022 for 3 tickers writes 3 month files, and `read_bars` returns exactly the synthetic rows for that range.
- `test_resume_skips_complete_months`: a second identical run reports all 3 months skipped, makes no source calls and writes nothing.
- `test_changed_tickers_refetch`: a run with a different ticker list fetches again.
- `test_bad_ticker_isolated`: the fake raises `BarsValidationError` for any batch containing `SYAB`. The other tickers are written, and `failed` holds one entry per month for SYAB.
- `test_pause_between_calls`: with `batch_size=2` and 3 tickers over 2 months, `sleep` is called 3 times (4 calls, none before the first), each with `pause`.
- `test_bad_args`: `start > end` and an empty ticker list raise.

## Out of scope
A CLI wrapper; building the ticker universe (current and delisted IDX tickers need their own source and chunk); running against the real network; committing data to the data repo.
