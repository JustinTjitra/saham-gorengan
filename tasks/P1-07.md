# P1-07: Data-quality flags

- **Phase:** P1
- **Model:** sonnet
- **Deps:** P1-01, P0-04
- **Size:** ~150 lines

## Goal
Flag bar rows that are suspicious as data, before any feature uses them: zero volume, stale flat prices, closes beyond the price limit in force, and prices that aren't on the tick grid. PLAN.md 3.1 needs these flags so that corporate actions and bad rows are excluded rather than silently adjusted.

## Files
- `src/saham_gorengan/quality.py` (new)
- `tests/test_quality.py` (new)

## Interface
```python
QUALITY_FLAGS: tuple[str, ...] = ("zero_volume", "stale_price", "beyond_limit", "off_tick")

def quality_flags(bars: pd.DataFrame, board: str = "regular") -> pd.DataFrame: ...
    """Columns: date, ticker, then one nullable "boolean" column per flag, in QUALITY_FLAGS order. Same rows and order as validate_bars(bars)."""

def quality_summary(flags: pd.DataFrame) -> pd.DataFrame: ...
    """Index = flag name. Columns: n_true (int), n_na (int), share_true (float, n_true / rows that are not NA), n_tickers (int, tickers with at least one True)."""
```

## Behaviour
- Call `validate_bars` first and never modify the input.
- "Previous close" means the close of the same ticker's previous bar, whatever the gap. Rows without one get `NA` for `stale_price` and `beyond_limit`.
- `zero_volume`: `volume == 0`. `NA` when volume is NaN.
- `stale_price`: open, high, low and close are all equal **and** equal the previous close.
- `beyond_limit`: let `lim = price_limits(day, prev_close, board)`. True if `close > lim.upper(prev_close) + tick_size(day, lim.upper(prev_close))` or `close < lim.lower(prev_close) - tick_size(day, max(lim.lower(prev_close), 1))`. The one-tick tolerance absorbs limit-price rounding. `NA` when `price_limits` or `tick_size` raises `ValueError` (date outside the tables).
- `off_tick`: `close` is not a whole multiple of `tick_size(day, close)`. `NA` outside the tick table. Compare with a tolerance of 1e-9 so float noise isn't flagged.
- Only data dated D or earlier is used for row D.
- A plain row-wise loop over `price_limits` and `tick_size` is acceptable. Correctness comes first; speed is out of scope.
- The module docstring must say that `board` applies to every row. Per-ticker board membership isn't known yet, so a watchlist-board stock checked with regular limits can be flagged wrongly.

## Acceptance
`tests/test_quality.py`:
- `test_zero_volume`: volume 0 → True, 100 → False, NaN → NA.
- `test_stale_price`: a flat bar equal to the previous close → True. A flat bar at a different price → False. A ticker's first bar → NA.
- `test_beyond_limit_regular_2024`: on 2024-01-02, prev close 100 (ARA 35%): a close of 135 → False, a close of 140 → True. A close of 64 (ARB 35% gives 65, minus a 1-rupiah tick tolerance gives 64) → False; 60 → True.
- `test_beyond_limit_fixed_rp1`: on 2026-10-20, prev close 8: 9 → False, 11 → True.
- `test_beyond_limit_before_tables`: a 2010 row → NA.
- `test_off_tick`: on 2024-01-02, 202 → False, 203 → True (tick 2), 5010 → True (tick 25), 5025 → False.
- `test_summary_counts`: hand-built flags give the expected n_true, n_na, share_true and n_tickers.
- `test_input_not_modified`.

## Out of scope
Fixing or dropping rows; corporate-action detection (P1-08); per-ticker board membership.
