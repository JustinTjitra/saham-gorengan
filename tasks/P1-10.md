# P1-10: Ticker-universe file loader and fetch plan

- **Phase:** P1
- **Model:** sonnet
- **Deps:** P1-09
- **Size:** ~110 lines

## Goal
Q5 asks the owner for a CSV of IDX tickers with listing and delisting dates. This chunk fixes that file's format and turns it into a per-ticker fetch plan for `backfill`, so the backfill can start as soon as the owner supplies the file. It also lets the delisted names (where pumped stocks concentrate) be fetched only for the period they traded.

## Files
- `src/saham_gorengan/universe.py` (new)
- `tests/test_universe.py` (new)
- `tests/fixtures/universe_sample.csv` (new; 4 placeholder rows, see Acceptance)

## Interface
```python
def load_universe(path: str | Path) -> pd.DataFrame: ...
    """Columns ticker (string), listed (datetime64[ns]), delisted (datetime64[ns], NaT = still listed), source (string)."""

def active_on(universe: pd.DataFrame, day: date) -> list[str]: ...
    """Sorted tickers listed on or before `day` and not delisted before `day`."""

def fetch_plan(universe: pd.DataFrame, start: date, end: date) -> pd.DataFrame: ...
    """Columns ticker, start, end (datetime64[ns]): each ticker's listed period clipped to [start, end]; tickers with no overlap omitted; sorted by ticker."""
```

## Behaviour
- The file is a UTF-8 CSV with header `ticker,listed,delisted,source`. Dates are ISO `YYYY-MM-DD`; `delisted` may be empty. `source` is where the row came from (a URL or a short note such as `broker export 2026-11`); it must not be empty.
- Validation (`ValueError` naming the line number):
  - a wrong header or a wrong field count (use `csv.reader`);
  - a ticker that is not 4 uppercase letters A-Z (IDX equity codes);
  - a bad date, or `delisted` earlier than `listed`;
  - a duplicate ticker;
  - an empty `source`.
- A ticker that relisted under the same code is out of scope: duplicates raise.
- `fetch_plan`: `start > end` raises `ValueError`. A delisted ticker's plan ends at its delisting date. A ticker listed after `end` or delisted before `start` is omitted.
- No network access, and no writes.

## Acceptance
- The fixture `tests/fixtures/universe_sample.csv` uses placeholder codes that are clearly not real tickers (`AAAA`, `BBBB`, `CCCC`, `DDDD`) with `source` = `test fixture`, because CLAUDE.md forbids invented label rows. Rows: AAAA listed 2010-01-04, still listed. BBBB listed 2018-05-02, delisted 2021-03-15. CCCC listed 2025-02-03, still listed. DDDD listed 2012-07-02, delisted 2015-12-30.
- `test_load_sample`: 4 rows, the right dtypes, and NaT for AAAA and CCCC.
- `test_active_on`: on 2020-01-02, AAAA and BBBB are active; on 2021-03-15, AAAA and BBBB; on 2021-03-16, only AAAA.
- `test_fetch_plan`: for [2016-01-01, 2024-12-31], AAAA runs 2016-01-01 to 2024-12-31 and BBBB 2018-05-02 to 2021-03-15; CCCC and DDDD are omitted.
- `test_validation`: write bad files to `tmp_path`, one each for a bad header, a lowercase ticker, a 5-letter ticker, delisted before listed, a duplicate ticker, an empty source and a wrong field count. Each raises `ValueError` whose message contains the line number.
