# P0-08: Loader rejects malformed CSV rows

- **Phase:** P0
- **Model:** sonnet
- **Deps:** none
- **Size:** ~50 lines

## Goal
Make the CSV loader fail loudly when a row has more or fewer fields than the header. During P0-02 an unquoted comma in a `notes` field produced an extra column. `csv.DictReader` silently put the overflow under a `None` key, so the notes were truncated and every test still passed.

## Files
- `src/saham_gorengan/_load.py`
- `tests/test_loader.py` (new)

## Interface
`_rows` keeps its signature. Its behaviour changes:
```python
def _rows(name: str) -> list[dict[str, str]]:
    """Rows of data/<name> as dicts. Raises ValueError if any row's field count differs from the header's."""
```

## Behaviour
- Read with `csv.DictReader(f, restkey=..., restval=...)`, or check `len(row)` with `csv.reader`. Either way, a row with **too many** fields and a row with **too few** fields both raise `ValueError`.
- The message names the file and the 1-based physical line number, e.g. `price_limit_regimes.csv line 31: expected 13 fields, got 14`.
- Blank trailing lines are not errors (DictReader already skips them; keep that).
- Correct files load exactly as before, and every existing public loader returns the same objects.

## Acceptance
In `tests/test_loader.py`, using `tmp_path` and `monkeypatch.setattr` on `saham_gorengan._load.data_dir` to point at a temp folder:
- `test_rows_reads_well_formed_file`: header `a,b` plus row `1,2` gives `[{"a": "1", "b": "2"}]`.
- `test_rows_rejects_extra_field`: header `a,b`, row `1,2,3` raises `ValueError`. The message contains `line 2` and the file name.
- `test_rows_rejects_missing_field`: header `a,b`, row `1` raises `ValueError`.
- `test_rows_quoted_comma_is_fine`: header `a,b`, row `1,"x, y"` gives `b == "x, y"`.
- `test_all_shipped_csvs_are_well_formed`: calls `_rows` on every `data/*.csv` without error.
- The whole suite passes.

## Out of scope
Changing any CSV in `data/`, the dataclasses or the validation in the per-table loaders.
