# P0-07: Task-board consistency test

- **Phase:** P0
- **Model:** sonnet
- **Deps:** none
- **Size:** ~120 lines

## Goal
A pytest module that fails whenever `tasks/BOARD.md` and the chunk specs in `tasks/` disagree. The loop then can't leave the board in a broken state without CI noticing.

## Files
- `tests/test_board.py` (new)

## Interface
Test-only module. Internal helpers are fine, for example:
```python
def parse_board(path: Path) -> list[dict[str, str]]: ...   # rows of the markdown table
def parse_spec_header(path: Path) -> dict[str, str]: ...    # {"Phase": ..., "Model": ..., "Deps": ...}
```

## Behaviour
- The board is the first markdown table in `tasks/BOARD.md`, with header `| id | title | phase | model | deps | status | commit |`. Ignore every line outside that table.
- A spec header line looks like `- **Model:** sonnet`. Read the `Phase`, `Model` and `Deps` fields from the first 10 lines of each spec.
- `deps` is `none` or a comma-separated list of ids (spaces allowed).

## Acceptance
All of these test the real repo files:
- `test_ids_unique`
- `test_every_row_has_spec`: `tasks/<id>.md` exists.
- `test_every_spec_has_row`: every `tasks/*.md` except `BOARD.md` and `TEMPLATE.md` appears on the board.
- `test_status_and_model_values`: status is in {todo, doing, done, blocked}; model is in {haiku, sonnet}.
- `test_deps_exist_and_acyclic`: every dep is a board id, and there is no cycle (DFS).
- `test_done_rows_have_commit`: rows with status `done` have a commit matching `^[0-9a-f]{7,40}$`.
- `test_spec_header_matches_board`: the spec's Model and Deps equal the board's, comparing deps as sets.

Each test must give a clear message naming the offending id. Write one extra test that runs the parser on an inline broken table (a cycle) and asserts the cycle is detected; use `tmp_path`.

## Out of scope
Changing `tasks/BOARD.md` or any spec. If the current files fail a test, report it rather than fixing the files.
