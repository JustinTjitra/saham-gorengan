# P5-06: Evaluation pipeline from features and label windows to report inputs

- **Phase:** P5
- **Model:** sonnet
- **Deps:** P5-05, P4-06
- **Size:** ~140 lines

## Goal
Wire the pieces together: label windows plus a feature panel plus detector ranks become one `DetectorResult` per detector, ready for `render_report`. Once real data lands, producing `reports/evaluation.md` is a single call.

## Files
- `src/saham_gorengan/evaluation/pipeline.py` (new)
- `tests/test_evaluation_pipeline.py` (new)

## Interface
```python
def windows_frame(windows: Iterable[Window]) -> pd.DataFrame: ...
    """Columns window_id, ticker (string), start, end (datetime64[ns]), in input order."""

def default_detectors(features: pd.DataFrame, include_iforest: bool = False) -> dict[str, pd.DataFrame]: ...
    """rank_ret, rank_vol, rank_rule, composite (and iforest if asked); each value has columns date, ticker, rank."""

def evaluate(features: pd.DataFrame, windows: pd.DataFrame, detectors: Mapping[str, pd.DataFrame],
             k: int = 25, lead: int = 20, n_placebo: int = 20, seed: int = 0) -> list[DetectorResult]: ...
```
`Window` comes from `saham_gorengan._load`; `DetectorResult` from `evaluation.report`.

## Behaviour
- `default_detectors` uses `baseline_scores`, `composite_scores` and, when asked, `iforest_scores`, all with default parameters, and renames each detector's rank column to `rank`.
- `evaluate`:
  - Keeps only windows whose ticker has at least one row in `features`, and computes placebos once: `placebo_windows(kept, features[["date", "ticker", "liq_bucket"]], n_per_window=n_placebo, seed=seed)`.
  - Builds one `DetectorResult` per detector, in mapping order:
    - `case_metrics` = `window_metrics(ranks, kept, k, lead)`;
    - `placebo_metrics` = `window_metrics(ranks, placebos, k, lead)`;
    - `random_metrics` = `window_metrics(random_ranks(ranks, seed=seed), kept, k, lead)`;
    - `burden` = `alert_stats(ranks, k)`.
  - Raises `ValueError` for an empty `detectors` mapping, for no kept windows, or for `features` without `liq_bucket`.
- Deterministic for a given seed. Inputs are not modified.

## Acceptance
`tests/test_evaluation_pipeline.py`, on a synthetic panel: `synthetic_bars(n_tickers=40, start=2024-01-02, end=2024-12-31, seed=0)` with one strong default `Pump` on one ticker starting at trading day 120, and its window running from that day for 15 trading days.
- `test_windows_frame`: two hand-made `Window` objects become a two-row frame with the right dtypes and order.
- `test_default_detectors_keys`: keys are rank_ret, rank_vol, rank_rule and composite (plus iforest when `include_iforest=True`), each with columns date, ticker, rank.
- `test_evaluate_shapes`: with `default_detectors` and `n_placebo=5`, every result has one case row, 5 placebo rows and one random row, and burden keys flags_per_day and distinct_tickers.
- `test_case_metrics_match`: each `case_metrics` equals `window_metrics(ranks, windows, k, lead)` called directly.
- `test_strong_pump_found`: the composite's case window is found.
- `test_unknown_ticker_dropped`: adding a window for a ticker not in the panel gives the same results as without it.
- `test_deterministic` and `test_render_roundtrip`: `render_report(evaluate(...), k, lead)` returns text that contains the pump ticker.
- `test_bad_input`: an empty mapping, all windows unknown, and a missing `liq_bucket` each raise.

## Out of scope
Writing `reports/evaluation.md`, stratified tables by regime or board (a later chunk), weak labels in the burden.
