# P2-09: Mask rolling-window features after a corporate-action day

- **Phase:** P2
- **Model:** sonnet
- **Deps:** P2-08
- **Size:** ~80 lines

## Goal
P2-08 masks only the corporate-action day itself. Rolling features for the following rows (cumulative returns, run-up, volume baselines and so on) still span the price jump, so a 5:1 split would look like an 80% crash for weeks. PLANNER_NOTES lists this as a known risk to fix before real data.

## Behaviour
- `WINDOW_FEATURES` = car_5, car_20, ara_run, vol_z, turnover_z, value_z, zero_vol_share, cumret_5, cumret_20, runup_20, drawdown_20, med_value_20, amihud_20, liq_bucket, vol_20, censored_share_20, vpt_z and freq_z, in `FEATURE_COLUMNS` order.
- **Same-day features** (every other column: ret, ret_norm, ara_hit, arb_hit, mkt_ret, car_1, turnover, value_est, parkinson, value_per_trade, net_foreign) are masked only on the event day, as now.
  - Exception: ret, ret_norm and car_1 on the row right **after** an event use the event-day close as `prev`. That is fine, because the event day's own row is already masked and the next day's return is a true trading return.
- `post_masked` is True on the `post_mask_rows` rows of the same ticker that follow a masked row. If events are closer together than that, the windows merge. On `post_masked` rows, set `WINDOW_FEATURES` to missing, keeping dtypes. `masked` rows keep `post_masked` False; they are masked entirely already.
- `post_mask_rows` must be an int ≥ 0 (bool rejected); 0 turns the new masking off.
- Column order: date, ticker, masked, post_masked, *FEATURE_COLUMNS. Update the existing column test accordingly.
