# P5-02: Leave-one-case-out splits with embargo

- **Phase:** P5
- **Model:** sonnet
- **Deps:** P5-01
- **Size:** ~90 lines

## Goal
Anything trained on labels (the PU ranker, P4-04) must be scored on a case it never saw, with an embargo of ±60 trading days so that nearby days of the held-out case cannot leak into training (PLAN.md 3.4). This chunk produces those splits; it trains nothing.

## Files
- `src/saham_gorengan/evaluation/splits.py` (new)
- `tests/test_evaluation_splits.py` (new)

## Interface
```python
@dataclass(frozen=True)
class Split:
    held_out: str                    # window_id
    train_days: pd.DatetimeIndex
    test_days: pd.DatetimeIndex

def loco_splits(days: Sequence, windows: pd.DataFrame, lead: int = 20, embargo: int = 60) -> list[Split]: ...
    """days: trading days (any order, duplicates allowed). windows: window_id, ticker, start, end. One Split per window, in windows order."""
```

## Behaviour
- Let T be the sorted unique trading days, and i(d) a day's position in T.
- For each window, the test days are T from position `max(0, i(first day >= start) - lead)` through `i(last day <= end)`. A window with no trading day inside [start, end] is skipped, so no Split is produced for it.
- The train days are every day in T whose position is **more than** `embargo` positions away from every test day, that is, outside [first_test - embargo, last_test + embargo].
- Embargo is per held-out window only. Other windows' days stay in training: their labels are the positives the model learns from.
- Validation: `lead` and `embargo` must be ints ≥ 0 (bool rejected). Missing window columns and duplicate window_ids raise `ValueError`.
- Pure function: no I/O, and inputs are not modified.

## Acceptance
`days` = 300 business days from 2024-01-01 (`pd.bdate_range`).
- `test_hand_example`: one window from T[100] to T[109], lead=20, embargo=60. Test days are T[80:110] (30 days). Train days are T[0:20] plus T[170:300] (150 days). Check the first and last train days around the gap: T[19] and T[170].
- `test_window_near_start`: start at T[5], end T[9], lead=20. Test days start at T[0]. Train days are T[70:300].
- `test_window_outside_days_skipped`: a window in 2030 produces no Split; the other windows still do.
- `test_no_overlap`: for every split, train and test are disjoint, and the smallest gap between a train day and a test day is > `embargo` positions.
- `test_order_and_ids`: two windows give two splits in windows order, with matching `held_out`.
- `test_bad_args`: lead -1, embargo `True`, a missing `end` column and duplicate window_ids each raise.

## Out of scope
Training any model (P4-04); rolling walk-forward for unsupervised detectors (P4-03 already refits strictly in the past).
