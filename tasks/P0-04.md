# P0-04: Tick-size table and helpers

- **Phase:** P0
- **Model:** sonnet
- **Deps:** none
- **Size:** ~140 lines

## Goal
Encode IDX tick sizes (fraksi harga) by date, so that later features can round limit prices and spot impossible prices.

## Files
- `data/tick_sizes.csv` (new)
- `src/saham_gorengan/ticks.py` (new)
- `src/saham_gorengan/__init__.py` (exports)
- `tests/test_ticks.py` (new)

## Interface
CSV header, exactly:
```
band_id,effective_from,effective_to,price_gte,price_lt,tick_idr,decree,source_url,notes
```
`price_lt` blank means no upper bound. Both dates are inclusive, and `effective_to` blank means still in force.

```python
@dataclass(frozen=True)
class TickBand: ...  # one field per CSV column, typed like RegimeTier

def load_tick_sizes() -> list[TickBand]: ...
def tick_size(day: date, price: float) -> int: ...
def round_to_tick(price: float, day: date, mode: str = "down") -> int: ...  # mode in {"down","up","nearest"}
```

## Behaviour
- Rows from 2016-05-02 (`Kep-00023/BEI/04-2016`), effective_to blank:
  - price under 200: tick 1
  - 200 to under 500: tick 2
  - 500 to under 2000: tick 5
  - 2000 to under 5000: tick 10
  - 5000 and above: tick 25
- Add the pre-2016 bands only if `trading_rules_history.md` gives their exact values and start date. Otherwise the table starts on 2016-05-02, and earlier dates raise `ValueError` ("before").
- The tick is looked up for the price itself: a price of exactly 200 has tick 2.
- `round_to_tick` rounds to a multiple of the tick of the *rounded* price's band. Using the band of the input price is acceptable if you document it. `nearest` resolves ties upward.
- Use the CSV loading style of `_load.py` (`data_dir()`, `csv.DictReader`, `lru_cache`).

## Acceptance

- Boundary table:
  - 199 → 1
  - 200 → 2
  - 499 → 2
  - 500 → 5
  - 1999 → 5
  - 2000 → 10
  - 4999 → 10
  - 5000 → 25
- `round_to_tick(203, d, "down") == 202`
- `round_to_tick(203, d, "up") == 204`
- `round_to_tick(5012, d, "nearest") == 5000`
- A date before coverage raises.
- An integrity test: within each period the bands are contiguous (each `price_lt` equals the next `price_gte`), and the periods themselves are contiguous.
