# P2-08: Feature assembler

- **Phase:** P2
- **Model:** sonnet
- **Deps:** P1-08, P2-01, P2-02, P2-03, P2-04, P2-05, P2-06, P2-07
- **Size:** ~120 lines

## Goal
One function that turns a bars panel into the full feature table every detector reads. It masks probable corporate-action days, which PLAN.md 3.1 says are excluded from features rather than adjusted.

## Files
- `src/saham_gorengan/features/assemble.py` (new)
- `tests/test_features_assemble.py` (new)

## Interface
```python
FEATURE_COLUMNS: tuple[str, ...]  # every feature column, in output order

def build_features(bars: pd.DataFrame, board: str = "regular") -> pd.DataFrame: ...
    """Columns: date, ticker, masked ("boolean"), then FEATURE_COLUMNS. Same rows and order as validate_bars(bars)."""
```

## Behaviour
- Call each feature function once on `bars` with default parameters (`board` passed where accepted):
  - `limit_features` (P2-01): ret, ret_norm, ara_hit, arb_hit, ara_run
  - `abnormal_returns` (P2-02): mkt_ret, car_1, car_5, car_20 (drop its `ret`, which duplicates P2-01's)
  - `volume_features` (P2-03): vol_z, turnover, turnover_z, value_z, zero_vol_share
  - `runup_features` (P2-04): cumret_5, cumret_20, runup_20, drawdown_20
  - `liquidity_features` (P2-05): value_est, med_value_20, amihud_20, liq_bucket
  - `volatility_features` (P2-06): parkinson, vol_20, censored_share_20
  - `tradesize_features` (P2-07): value_per_trade, vpt_z, freq_z, net_foreign
- `FEATURE_COLUMNS` is exactly those columns in that order. Join on (date, ticker); every function already returns `validate_bars` row order, but join by key, not position, and assert the row count is unchanged.
- `masked` is True where `corporate_action_suspects(bars, board)["suspect"]` (P1-08) is True; NA counts as False. On masked rows, set every feature to missing (NaN for floats, NA for nullable types), keeping each column's dtype. `liq_bucket` is masked too.
- Dtypes are those of the source functions.
- Note in the docstring that masking can use Yahoo's after-the-fact adjusted close (P1-08 rule 2). That is acceptable for removing split days, which are announced in advance, but `masked` itself must not be used as a feature.

## Acceptance
`tests/test_features_assemble.py`:
- `test_columns_and_rows`: on `synthetic_bars(n_tickers=8)`, the output has `["date", "ticker", "masked", *FEATURE_COLUMNS]`, the same row count and order as `validate_bars`, no duplicate (date, ticker), and `masked` all False.
- `test_dtypes_preserved`: `ara_hit` is "boolean", `liq_bucket` and `ara_run` are "Int64", and `ret_norm` is float64.
- `test_split_day_masked`: a hand-built ticker in 2024 with closes 1000 for 25 days, then 200 (a 5:1 split, beyond the 25% limit for that tier). The split row has `masked` True and all features missing; the row before it is unmasked.
- `test_matches_components`: for one unmasked row of the synthetic panel, `vol_z`, `car_5` and `runup_20` equal the values from calling those feature functions directly.
- `test_no_lookahead`: `assert_no_lookahead(build_features, synthetic_bars(n_tickers=6))` passes.
- `test_input_not_modified`.

## Out of scope
Writing features to the store (a later chunk); per-ticker board membership.
