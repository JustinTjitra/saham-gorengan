# P4-07: Price-only trend-persistence detector

- **Phase:** P4
- **Model:** sonnet

## Goal
The P5-03b sweep showed that every detector relies on volume: slow pumps of 0.5 to 1% a day at normal volume are at chance level. This chunk adds a detector that scores steady drift in returns, independent of volume, and adds it to the recovery harness so it can be compared with the others.

## Behaviour
- For each ticker, over the trailing `window` rows up to and including D (row-based, in date order): `s_trend = mean(ret) / std(ret, ddof=1) * sqrt(n)`, where n is the number of non-missing `ret` in the window. This is the t-statistic of the drift.
- `s_trend` is NaN when n < `min_periods`, or when std is 0 or NaN. Missing `ret` (masked days) count as missing, not as 0.
- `rank`: per date, use `baselines._rank(df, "s_trend")` (1 = highest s_trend, ties by ticker, NA where NaN).
- Validation: `window` must be an int ≥ 2, and `min_periods` an int with 2 ≤ min_periods ≤ window (bool rejected). Both raise `ValueError`, as do a missing column and duplicate (date, ticker) rows.
- Output is sorted by (date, ticker) with a fresh RangeIndex. The input is not modified. Use groupby-rolling, not a per-ticker Python loop.
- `run_recovery(include_trend=True)` adds `"rank_trend"`, computed from the same `features` with default parameters and scored the same way. With `include_trend=False` (the default), the output is unchanged; `recovery_sweep` is unchanged.

## Acceptance
`tests/test_detectors_trend.py`:
- `test_hand_example`: one ticker with `ret` = [0.01, 0.03, 0.02, 0.04], `window=4`, `min_periods=4`. Rows 0-2 are NaN; row 3 is 3.872983 (± 1e-6).
- `test_masked_rows_skipped`: the same with a NaN inserted as the third value (5 rows), `window=5`, `min_periods=4`. The last row equals the hand example's value.
- `test_rank_order`: two tickers on one date; the higher s_trend gets rank 1.
- `test_no_lookahead`: `assert_no_lookahead` with a wrapper that runs `build_features` and then `trend_scores` on `synthetic_bars(n_tickers=6)`.
- `test_bad_args`: window 1, min_periods 1, min_periods > window, `True`, a missing `ret` column and a duplicate row each raise `ValueError`.
- `test_recovery_trend_strong_price_only`: mean of `run_recovery(seed=s, n_tickers=150, n_pumps=10, k=5, daily_return=0.02, volume_mult=1.0, include_trend=True)["rank_trend"]` over seeds 0 and 1 is ≥ 0.8. (Planner estimate: a 10-day t-statistic of about 3.2 against a top-5-of-150 threshold near 2.)
- `test_recovery_default_unchanged`: `run_recovery(seed=0)` has no `"rank_trend"` key.

In your final report, also give the table of mean recall over seeds 0 and 1 (n_tickers=150, n_pumps=10, k=5, volume_mult=1.0) for daily_return in (0.005, 0.01, 0.02), for rank_trend, composite and random (`include_random=True`). If the 0.8 threshold fails, report the table and stop: do **not** loosen it or tune the detector.
