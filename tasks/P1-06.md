# P1-06: Trading calendar and missing-day flags

- **Phase:** P1
- **Model:** sonnet
- **Deps:** P1-01
- **Size:** ~130 lines

## Goal
Derive the IDX trading calendar from the panel itself, and flag days on which a listed ticker has no bar. PLAN.md 3.1 treats a missing day as a suspension proxy, and that flag must never be forward-filled into a fake price.

## Files
- `src/saham_gorengan/calendar.py` (new)
- `tests/test_calendar.py` (new)

## Interface
```python
def trading_calendar(bars: pd.DataFrame, min_share: float = 0.5) -> pd.DatetimeIndex: ...
    """Sorted unique dates on which at least ceil(min_share * median daily ticker count) tickers have a bar."""

def missing_day_flags(bars: pd.DataFrame, calendar: pd.DatetimeIndex | None = None) -> pd.DataFrame: ...
    """One row per (date, ticker) for every calendar date from the ticker's first bar to the calendar's last date.
    Columns: date (datetime64[ns]), ticker (string), missing (bool), gap_len (Int64)."""
```

## Behaviour
- Both functions call `validate_bars` on the input first and never modify it.
- `trading_calendar`: count distinct tickers per date and take the median of those counts. A date is a trading day if its count is at least `max(1, ceil(min_share * median))`. This drops stray dates that only one or two tickers report. An empty panel returns an empty `DatetimeIndex`. `min_share` outside (0, 1] raises `ValueError`.
- `missing_day_flags`: `calendar` defaults to `trading_calendar(bars)`.
  - A ticker's rows start at its **first** bar and run to the **last calendar date**, not to the ticker's last bar. Stopping at the last bar would use the future: on day D nobody knows a stock will never trade again.
  - `missing` is True when the ticker has no bar on that date. A bar with `volume == 0` or NaN volume is **not** missing.
  - `gap_len` counts consecutive missing calendar days up to and including that date: 0 when not missing, then 1, 2, 3 and so on.
  - Bars on dates outside `calendar` are ignored.
  - The output is sorted by (date, ticker) with a fresh RangeIndex.
- No look-ahead: the row for (D, ticker) depends only on bars dated D or earlier. One exception is the calendar itself, which is built from the whole panel. Say so in the module docstring.

## Acceptance
`tests/test_calendar.py`, building small frames with `validate_bars`:
- `test_calendar_drops_sparse_dates`: 10 tickers on 5 dates plus a sixth date where 1 ticker reports. The calendar has the 5 dates.
- `test_calendar_empty`: `empty_bars()` gives an empty index.
- `test_calendar_bad_min_share`: 0 and 1.5 both raise.
- `test_missing_flags_gap_len`: ticker AAAA trades on days 1, 2 and 5 of a 6-day calendar. Rows run days 1-6; `missing` is F,F,T,T,F,T and `gap_len` is 0,0,1,2,0,1.
- `test_rows_start_at_first_bar`: a ticker first trading on day 3 has no rows for days 1-2.
- `test_zero_volume_is_not_missing`.
- `test_no_lookahead`: `missing_day_flags(bars[bars.date <= D], calendar[calendar <= D])` equals the full result's rows with date <= D, for each D in the calendar.
- `test_input_not_modified`.
